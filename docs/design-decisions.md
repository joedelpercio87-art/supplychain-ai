# Design Decisions

These decisions describe the current portfolio demonstration. Production evolution items are possibilities, not implemented capabilities.

| Decision | Why | Tradeoff | Production evolution |
| --- | --- | --- | --- |
| Use synthetic data instead of employer or proprietary data. | Keeps the demonstration shareable and avoids exposing confidential operational records. A seeded scenario still exercises multi-table investigation. | Synthetic distributions cannot represent every real-world process or data-quality issue. | Use approved, minimized, governed datasets with explicit access controls and privacy review. |
| Use TypeScript and Node.js end to end. | Keeps the UI, API, agent orchestration, tools, MCP adapter, and data generation in one typed ecosystem. Node also supplies the local SQLite and TypeScript execution features used here. | A single language ecosystem may not match every enterprise data team's preferred tooling. | Integrate with existing service boundaries while keeping typed contracts across them. |
| Keep business tools deterministic. | Metric definitions and joins are easier to inspect, validate, and repeat when executed in SQL and TypeScript rather than estimated by a language model. | Every new business capability requires explicit implementation and maintenance. | Add versioned metric contracts, data-quality checks, and ownership for definitions. |
| Use LLM synthesis rather than LLM calculations. | The model selects capabilities and explains results; fixed queries calculate KPIs and return structured facts. | The answer still depends on correct tool selection and model synthesis. | Evaluate tool selection, numerical grounding, and answer consistency with repeatable datasets and regression cases. |
| Start with local SQLite. | Makes setup portable, inexpensive, and reproducible without requiring a database service. | It is not a shared enterprise warehouse or a multi-user operational store. | Connect to governed Snowflake/warehouse, ERP, or WMS sources according to workload and access needs. |
| Chunk policy documents by Markdown section. | Headings preserve topic boundaries and make retrieved passages easier to interpret and cite. Oversized sections can be split while retaining section metadata. | Heading quality and section length affect retrieval precision. | Add document versioning, policy ownership, access metadata, and retrieval evaluations. |
| Store the vector index locally. | Keeps this demonstration self-contained and avoids an external vector database dependency. | The JSON index has limited scaling, lifecycle, and concurrent-update capabilities. | Select a managed or self-hosted vector service only when scale, availability, or governance requires it. |
| Build direct tools first, then add MCP. | Direct calls establish and validate business logic before introducing a protocol boundary. Both paths can be compared while reusing the same functions. | Maintaining two agent entry points creates some duplicated orchestration surface. | Decide whether to retain both based on client reuse and governance needs; keep one authoritative implementation of each capability. |
| Use stdio MCP before remote MCP. | Stdio offers local protocol discovery and invocation without exposing a network endpoint. | It is limited to local processes and is not usable as a shared remote service. | Add remote transport only with authentication, authorization, transport security, rate limits, and operational ownership. |
| Show an observable tool trace without chain-of-thought. | Users can inspect requested tools, sanitized arguments, summaries, and retrieved policy sources without exposing private reasoning. | Summaries are less detailed than raw execution payloads, and a trace is not a full audit log. | Add durable, access-controlled event records, privacy policies, and audit retention appropriate to the deployment. |
| Preserve evidence boundaries in responses. | Separating observed facts, interpretation, policy, recommendations, and gaps helps users judge what the data supports. | Cautious language can make a response less definitive when relationships are incomplete. | Add explicit lineage and relationship coverage, plus evaluation for unsupported causal claims. |
| Build the UI after backend capabilities were validated. | Deterministic tools, retrieval, and MCP can be exercised before adding a presentation layer. The UI can then display actual returned context rather than parallel calculations. | The first UI adapter needed a small additive metadata contract for charting and evidence presentation. | Keep the UI as a consumer of API contracts and avoid duplicating business definitions in presentation code. |
